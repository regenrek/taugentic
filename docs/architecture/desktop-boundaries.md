# Desktop boundaries

`apps/desktop` contains one macOS desktop app. React describes the interface,
GPUIX renders it through GPUI, and `@taugentic/desktop-daemon-native` owns the
in-process client lifecycle to the Taugentic daemon.

## Ownership

### Taugentic desktop owns

- window composition and navigation
- temporary form, focus, and panel state
- presentation of daemon snapshots and events
- the uncommitted runtime, auth-profile, and model selection draft
- construction and cleanup of the Rust-owned native daemon bridge

The desktop does not own sockets, credentials, session authorities, sessions,
runs, approvals, permissions, persistence, harness selection, model metadata,
replay order, or daemon recovery policy.

### `ta-desktop-native` owns

- starting the canonical runtime-control operation
- the direct persistent daemon client
- credentials, rotating session authorities, socket paths, and event cursors
- replay-before-live delivery, cancel, and close
- one run-event subscription, released on terminal delivery, cancellation,
  stream closure, conversation or project change, and bridge close
- one redacted daemon lifecycle projection: Rust retains daemon identity and
  epoch-aware cursors, while desktop receives only status, invalidation,
  snapshot-rehydration intent, and a foreign-runtime restriction
- redacted `daemon.session.open` projection; returned session authorities stay
  in the Rust credential store
- an opaque Rust-only runtime-control handle whose only operation is release;
  it conditionally closes only the exact daemon instance started for that
  bridge lifecycle

It returns only redacted JSON whose shape is generated by `ta-protocol`. No
TypeScript socket, runtime-control, literal authority, or handwritten JSON-RPC
path may exist in the desktop.

The lifecycle projection never exposes daemon instance IDs, cursors, socket or
log paths, transport errors, process identity, handles, or control authority.
`foreignRuntimeRestricted` is display-only: it can never trigger stop,
reconcile, replacement, or any other runtime control action.

### Daemon-owned navigation domain

The daemon owns durable navigation metadata and the only navigation snapshot.
Spaces, projects (including an optional space membership for Ungrouped),
project-to-canonical-`WorkspaceId` membership, conversation placement, pins,
archive state, and temporary-conversation deletion are validated and persisted
in Rust. A conversation is the existing `SessionId`; title and status are
derived from its canonical session projection at snapshot time and are never
persisted in navigation metadata. There is no `ThreadId`, Agent table,
Attention table, or duplicate Workspace record. Agent rows and approval
attention are derived from existing session/run/approval projections. A
temporary conversation can be deleted only once all of its runs are terminal
and it has no pending approval; its session-owned history is deleted atomically.
The native bridge exposes only generated snapshot JSON and typed intent JSON,
never credentials, session authorities, daemon identity, paths, cursors,
process handles, or runtime control.

### Daemon-owned run routes

The daemon projects runtime profiles, auth methods, connected auth profiles,
and provider models. The desktop keeps an uncommitted route draft and submits
its explicit IDs as one `AgentRuntimeSelection` in `StartRunCommand`. The
desktop does not apply or persist the draft through a separate daemon call.
The daemon validates the command against current durable auth state immediately
before scheduling and records one immutable `RunExecutionRoute` on the run.
The desktop never infers a provider, model, auth profile, or harness.

The desktop merges replay and live events by sequence. A terminal run event,
cancellation, stream closure, conversation change, project change, or desktop
close releases the one native subscription and clears presentation state.

### GPUIX owns

- the React reconciler
- the retained native element tree
- GPUI window creation, rendering, focus, text input, scrolling, and events
- the JavaScript-to-Rust bridge
- native desktop test automation

GPUIX must not contain Taugentic product state or daemon policy.

### `packages/shared` owns

`packages/shared` is generated output from `ta-protocol`. It exposes transport
types to TypeScript and contains no handwritten policy, validation, defaults, or
runtime code.

Run these commands after a protocol change:

```sh
cargo xtask export-protocol --expect-write generated/ChangedType.ts --expect-delete generated/RemovedType.ts
cargo xtask check-protocol
```

Repeat either declaration flag for every generated path in the candidate diff;
one side may be absent, but the declared union must be nonempty and exact.

## Dependency direction

The dependency direction is fixed:

```text
Taugentic React app -> GPUIX -> GPUI
Taugentic React app -> generated ta-protocol types
Taugentic React app -> ta-desktop-native -> ta-daemon-client -> ta-jsonrpc
```

Do not add a preload layer, desktop IPC bridge, browser renderer, or second
desktop state owner. Put product behavior in the Taugentic app, native rendering
behavior in GPUIX, and runtime behavior in the daemon.

## Dependency policy

Taugentic pins `@regenrek/gpuix-react` to an exact published version. That
package pins `@regenrek/gpuix-native` and its platform packages to the same
exact fork release, so the reconciler, bridge, and native binary cannot move
independently. The fork adds native features required by Taugentic while GPUIX
remains the upstream rendering owner.

Upgrade the complete fork package family in one change. Run the type check,
the native live-window test, and the manual milestone test before accepting
the upgrade.

pnpm delays other new package releases for seven days and rejects downgraded
registry trust signals. The GPUIX fork packages and their direct event parser
are explicit exceptions because Taugentic pins and reviews each fork release.
`ta-jsonrpc` owns one Tokio local-socket actor per persistent client. Its sole
reader correlates responses and fans out notifications through bounded queues;
lag is reported as a terminal backpressure error rather than blocking the
reader. The native bridge exposes Promise operations and nonblocking callbacks,
never a synchronous event read.
# M1 local evidence

`just measure-m1` builds the desktop boundary and local daemon in release mode, runs one credentials-free isolated local-daemon sample, and writes its non-sensitive measurement record only to ignored temporary storage. The record identifies the build, fixture, commit, OS/architecture class, sample count, declared ready/close budgets, and measured values. Authenticated provider metrics remain manual evidence because existing user profiles and quota are never injected into automation.
